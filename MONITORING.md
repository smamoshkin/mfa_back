# Мониторинг прода

Дашборд моментального статуса + email-алерты при поломках. История метрик не хранится.

## Дашборд

- URL: `https://faapp.ru/status/` (basic auth, креды у владельца)
- Статусы: зелёный (ok) / жёлтый (warn) / красный (fail) по каждой проверке
- Автообновление страницы — каждые 15 сек; сами проверки выполняются по cron раз в час
- Проверки API/фронта/домена идут через основной вход `https://faapp.ru` (включая срок сертификата)
- Стек: статическая страница `status/index.html` читает `status/status.json`, оба файла отдаёт nginx-контейнер (см. `location /status/` в `nginx/nginx.conf`)

## Скрипт-санитар `~/bin/health_check.sh` (на сервере)

Запускается cron'ом раз в час (`0 * * * *`). Последовательность:

1. Выполняет проверки и пишет `~/marketfinanceapp/status/status.json` (источник данных дашборда)
2. Сравнивает статусы с прошлым запуском (`~/status_state.json`)
3. При переходе проверки в fail — отправляет email-алерт; при возврате в ok — письмо о восстановлении. Алерты только на смену статуса, чтобы не спамить.

### Список проверок

| Проверка | Критерий |
|---|---|
| Контейнеры (7 шт: backend, frontend, nginx, celery, celery_beat, db, redis) | running и не в цикле рестартов |
| API | `GET /api/docs` отвечает 200 |
| Фронтенд | `GET https://faapp.ru/login` отвечает 200 |
| Домен | `GET https://faapp.ru/` 200 + срок действия сертификата |
| БД | ответ на `SELECT 1` (+ размер БД в detail) |
| Celery | `celery inspect ping` — воркер отвечает |
| Синхронизация WB | последняя успешная задача в `tenant_sync_jobs` не старше 8 дней (sync еженедельный) |
| Диск | warn ≥ 70%, fail ≥ 85% |
| Память | warn ≥ 85%, fail ≥ 95% |
| Бэкап БД | свежий файл `~/backups/db_*.sql.gz` не старше 8 дней |

## Настройка алертов

SMTP-креды для отправки писем — в `~/bin/.alert_smtp.conf` на сервере (права 600, формат: `SMTP_URL`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`, `MAIL_TO`). Отправка — через curl (smtps), без установки почтовых агентов.

Адресат и отправитель намеренно не публикуются в репозитории.

При появлении бот-платформы в нужном мессенджере: заменить функцию `send_email()` в `health_check.sh` (она изолирована, ~15 строк).

## Ручные операции

```bash
~/bin/health_check.sh                                  # прогнать проверки прямо сейчас
tail -50 ~/marketfinanceapp/status/health.log          # лог проверок и алертов
crontab -l                                             # расписание (бэкап вс 03:00, health каждый час)
```

## Связанные файлы

- `nginx/nginx.conf` — location /status/ c basic auth (пароль: `nginx/.htpasswd` на сервере)
- `docker-compose.prod.yml` — монтирование `./status` и `.htpasswd` в nginx-контейнер
- Бэкапы БД: скрипт `~/bin/backup_db.sh`, детали — `DEPLOY.md` и `LOCAL_RUNBOOK.md`
